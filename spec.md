# Telegram CRM Bot — спецификация

## Problem Statement

Малый бизнес получает заявки в Telegram, но без единого реестра менеджер может потерять обращение, забыть следующий шаг или не увидеть просроченную заявку. Работодателю нужен проверяемый портфолио-кейс, который показывает не только диалог бота, но и хранение, правила статусов, аудит и выгрузку.

## Solution

Локально воспроизводимый Python-проект принимает заявку через Telegram-диалог, сохраняет её в SQLite, отправляет менеджеру структурированное уведомление, позволяет менять статус inline-кнопками и формирует статистику и Excel-выгрузку. Без токена та же бизнес-логика проверяется через тесты и демонстрационный генератор; автономный HTML-кейс показывает реальный маршрут заявки.

## User Stories

1. Как клиент, я хочу начать понятный диалог командой `/start`, чтобы быстро оставить заявку.
2. Как клиент, я хочу последовательно указать имя, телефон, услугу, комментарий и удобное время, чтобы менеджер получил полный контекст.
3. Как клиент, я хочу получить понятную ошибку при неверном телефоне, чтобы исправить ввод.
4. Как клиент, я хочу подтвердить заявку перед сохранением, чтобы избежать случайной отправки.
5. Как клиент, я хочу получить номер заявки после сохранения, чтобы ссылаться на неё.
6. Как менеджер, я хочу получить новое обращение с ключевыми полями, чтобы сразу начать работу.
7. Как менеджер, я хочу взять заявку в работу, отложить или закрыть её inline-кнопкой, чтобы реестр оставался актуальным.
8. Как менеджер, я хочу видеть отказ в недопустимом переходе статуса, чтобы история не искажалась.
9. Как менеджер, я хочу открыть последние заявки командой `/leads`, чтобы увидеть очередь.
10. Как администратор, я хочу получить статистику командой `/stats`, чтобы оценить текущую нагрузку.
11. Как администратор, я хочу выгрузить заявки командой `/export`, чтобы проверить их в Excel.
12. Как проверяющий, я хочу запустить локальную демонстрацию без Telegram-токена, чтобы подтвердить бизнес-логику.
13. Как проверяющий, я хочу видеть историю каждого изменения статуса, чтобы действия были аудируемыми.
14. Как пользователь клавиатуры, я хочу видеть фокус в HTML-кейсе и отключать движение системной настройкой, чтобы интерфейс оставался доступным.
15. Как работодатель, я хочу за несколько минут понять проблему, архитектуру, ошибки и результат, чтобы оценить junior Python / Automation навыки.

## Implementation Decisions

- Python 3.11+; код, имена модулей, функций и тестов — на английском.
- Пользовательские тексты, README, HTML-кейс и отчёты — на русском.
- Aiogram 3.27 использует `Router`, явные FSM-фильтры, типизированный `CallbackData` и dependency injection через workflow data.
- SQLite хранит заявки и отдельную append-only историю статусов.
- Публичная сервисная граница: создать заявку, получить список, изменить статус, получить статистику, экспортировать Excel.
- Статусы: `new`, `in_progress`, `postponed`, `done`; переходы проверяются доменным правилом.
- Телефон нормализуется только при однозначном российском формате; неоднозначный ввод отклоняется, а не исправляется молча.
- Токен и ID менеджеров читаются только из окружения; `.env.example` не содержит секретов.
- Демонстрационные данные полностью синтетические и явно помечены.
- HTML-кейс автономный: без CDN, внешних шрифтов и серверного API.

## Testing Decisions

- Основной тестовый шов — публичный `LeadService`, наблюдаемый через возвращаемые модели и исключения.
- Отдельный шов экспорта — готовый XLSX, проверяемый по названиям листов и фактическим значениям.
- Бот-хендлеры остаются тонкими; Telegram API не используется для проверки доменной логики.
- Тесты используют временную SQLite-базу и не создают реальные сообщения или облачные записи.
- Проверяются валидное создание, отказ на плохом телефоне, разрешённые и запрещённые переходы, история, статистика, порядок списка и Excel.

## Out of Scope

- Веб-CRM, PostgreSQL, Docker и Google Sheets.
- Реальный продакшен-хостинг и webhook.
- Оплата, авторизация клиентов и рассылки.
- Автоматическое изменение статуса без действия менеджера.
- Реальные клиенты, коммерческие показатели, отзывы и отправка тестовых сообщений без отдельного пользовательского запуска.

## Further Notes

- Предметная область демо: заказы на цифровые услуги — Telegram-бот, CRM, Excel-отчёт, AI-помощник.
- Визуальное направление утверждено: «Операционный интерфейс», R03 Omnira + R02 LIA, без фиолетовых градиентов.
- Внешние зависимости: `aiogram`, `aiosqlite`, `openpyxl`, `python-dotenv`; тесты — `pytest`, `pytest-asyncio`.

## Acceptance Criteria

1. Локальная демонстрация создаёт синтетические заявки, историю статусов, статистику и Excel без сети.
2. Все доменные тесты проходят на чистой временной базе.
3. Telegram-приложение стартует только при наличии валидной конфигурации и не раскрывает токен.
4. Экспорт содержит листы `Заявки`, `История`, `Сводка` и не теряет исходные поля.
5. Автономный HTML-кейс показывает путь `new → in_progress → done`, очередь, таймер, напоминание и экспорт.
6. HTML не имеет горизонтального переполнения на 360, 768, 1208 и 1440 px и уважает `prefers-reduced-motion`.
7. README позволяет воспроизвести демо и отдельно объясняет подключение Telegram.
